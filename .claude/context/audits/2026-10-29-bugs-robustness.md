# Audit: bugs and robustness

Date: 2026-10-29
Baseline commit: af78a36
Scope: `src/`, `templates/web/.claude/hooks/` (correctness and robustness of the lib at 1.7.1)
Status: closed

## Findings

| ID | Severity | File | Problem | Status | Notes (commit / reason) |
|----|----------|------|---------|--------|-------------------------|
| B1 | high | templates/web/.claude/hooks/git-guard.mjs (`nestedTexts`, `gitCommands`) | A commit message body is parsed as commands. With the standard heredoc style `-m "$(cat <<'EOF' ... EOF)"`, a body line starting with `git ...`, or a backticked `` `git reset --hard` `` in the body, makes `decide()` return deny ("destructive command") for git-operator, blocking commits that describe git commands. Same for the main session on any heredoc that mentions git. | fixed | Reproduced with decide(): heredoc body with backticked `git reset --hard` gives deny for git-operator; body line `git checkout -- . is now denied` gives deny. Fix: `heredocs()` cuts the bodies out before `strip()`, `nestedTexts()` and the segment split; a quoted delimiter drops the body, an unquoted one only keeps its `$(...)` and backtick substitutions. `<<` only counts outside quotes and `$((...))`. |
| B2 | high | templates/web/.claude/hooks/git-guard.mjs (`decide`, `currentBranch`) | The protected-branch check uses the branch read before the command runs, so `git switch main && git commit -m x` or `git checkout develop && git pull` is allowed for git-operator from a feature branch: the confirmation on protected branches is bypassed. | fixed | Reproduced with decide() (branch feat/x, protected main and develop): both return allow. Fix: `decide()` walks the git commands in order and tracks the effective branch with `branchAfter()` (`switch`/`checkout`, `-c/-C/-b/-B` take the new name); an unparseable target (`-`, `--detach`, `$VAR`) makes it unknown, which asks. It tracks a set of possible branches: an ambiguous `checkout <x>` adds `x` to the set. |
| B3 | medium | src/install.js (`mergeSettings`) | When the kit changes a hook command, the array union keeps the old entry next to the new one, so the hook runs twice. After uninstall, `stripSettings` only removes the current kit entry: the old one stays and points to a deleted script. Already noted in the 2026-10-23 simplification review, still present. | fixed | Reproduced: mergeSettings(old PreToolUse hook, new kit hook) returns both entries. Fix: `dropKitEntries()` runs before the merge and the strip; it removes the hooks and the `statusLine` whose command ends on a kit script (the last `.claude/hooks/<name>` path, names read from the kit's own settings), drops emptied groups, and keeps the developer's own hooks. |
| B4 | medium | src/install.js (`planFiles`, settings branch) | The merge runs at every init or update once settings.json is edited, even when the kit did not change it: a kit allow or deny rule or hook the developer removed on purpose is added back each time. | fixed | From reading the branch order in planFiles. Fix: the settings merge only runs when the kit's settings changed (`recorded !== wanted`, or none recorded); after a merge the kit's hash is recorded, so an unchanged kit gives `kept` and the developer's removals survive. Known limit: when the kit does change settings.json, the merge still adds back every kit entry, removed ones included, because the previous kit content is not stored (a snapshot in the manifest would be more state than wanted). |
| B5 | medium | templates/web/.claude/hooks/git-guard.mjs (`READ`, `writes`) | False positives for the main session (deny on reads): `git stash show`, `git remote get-url` or `show`, `git config <key>`, `git check-ignore`, `git symbolic-ref`, `git worktree list`, `git help`, `git diff-tree`, `git name-rev`, `git cherry`. | fixed | Reproduced with decide(), agent empty: each returns deny. Fix: the pure read subcommands join `READ`; `writes()` reads `stash list/show`, `remote` (none, `-v`, `get-url`, `show`), `worktree list`, `config` (listing, `--get*`, one key; `configWrites`) and `symbolic-ref` with one name (`symbolicRefWrites`). Anything unclear stays a write. |
| B6 | low | templates/web/.claude/hooks/git-guard.mjs (`LEADING`, segment split) | Not detected (decide returns null): `timeout 10 git commit`, `sleep 1 & git commit` (`&` is not a separator), `git 'commit'`. The guard is a safety net (team decision), but `timeout` and `&` can happen by accident. | fixed | Reproduced with decide(), agent empty. Fix: `LEADING` takes `timeout` (options, duration) and `stdbuf` (options); the segment split also cuts on a single `&` (not `&&`, `2>&1`, `>&2`, `&>file`); a quoted subcommand makes `parseGit` return `UNKNOWN` (deny for the main session, ask for git-operator). |
| B7 | low | templates/web/.claude/hooks/run-node.sh (`latest_in`) | `sort -t. -k1.1,1n -k2,2n -k3,3n` splits the whole path on dots (`.nvm`, the version), so it sorts on the wrong fields: among v18.20.4, v22.11.0 and v24.2.0 it picks v18, while the comment promises the highest version. | fixed | Reproduced by piping the three nvm paths through the same sort. Fixed: `latest_in` now takes the `vMAJOR.MINOR.PATCH` of the path, prints a zero-padded numeric key then the path, sorts on the key and keeps the last usable node. |
| B8 | low | src/uninstall.js (`planUninstall`) | A manifest that is an object without `answers` (hand-edited) crashes `render()` with a raw TypeError; `readManifest` only checks the object shape. | fixed | `runUninstall` throws `.claude/brigade.json has no "answers" object…` before planning or writing; init/update untouched (`previous?.answers ?? {}`). |
| B9 | low | src/prompt.js (`choose` with "Other…") | An empty "Other…" answer is accepted (`text` without `required`): `baseBranch: ""` silently drops its protection, or an empty language lands in brigade-options.md. | fixed | `choose` "Other…" now asks `text(..., "", { required: true })`: a blank answer is refused ("Please type something."). Tested through a child process fed on stdin. |
