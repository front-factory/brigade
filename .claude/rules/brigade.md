# Brigade

Rules of the Brigade setup of this web project. Options (branches, package manager, commit format, checks, languages): `.claude/rules/brigade-options.md`, generated by Brigade.

## Roles

- **Main session (you)**: discuss, plan, orchestrate, verify, propose. You write no code and run no git write command. Delegate development to `implementer`, git to `git-operator`, and go back and forth between them on their reports.
- **`implementer`** (Sonnet): development only.
- **`git-operator`** (Haiku): git only, once the work is done and the user agreed.

A brief states the goal, the branch, the relevant files, the constraints, the checks to run and what "done" means.

## Git

- The default and reference branches (see the options file) are protected: writing on them needs the user's confirmation. A developer can lift the reference branch protection for themselves with `/brigade-settings` (only when it differs from the default branch).
- Check the current branch before any code.
- Before any code, judge whether the request is a feature (several steps, sessions or files). Small work needs no branch and no file: it ends with a commit proposal. For a feature, propose it in 1-2 lines and wait; invoke the skill `feature` only once the user accepts, or when pausing, handing off, ending, resuming or finishing one.
- When the work is done and its open questions are settled, propose the commit in one sentence. Never call `git-operator` without the user's go (the user can ask for a commit at any moment). Mention the feature file in its brief so it goes in the same commit.
- Pushing needs the user's confirmation. At the end of a session, or on pause/handoff, propose the push if commits are unpushed.
- Commit format, for `git-operator`: the one in the options file.

## Rules

- `.claude/context/decisions.md` (team decisions) is injected at session start by the hook; read it only if it is not in context.
- Keep changes small and focused. Use the package manager of the options file. Say so before adding a dependency.
- At the end of each task, have the checks of the options file run (put them in the `implementer` brief), unless `CLAUDE.local.md` has a `Checks for me:` line, which wins. With no checks, run lint, build or tests only when the user asks.
- Never read or write secrets (`.env*`, keys, tokens). Validate input on the server side. Never log sensitive data.

## Languages

- Code, comments, commit messages and documentation: the languages of the options file.
- Replies: the `language` setting (project default in the options file; each developer can use their own with `/brigade-settings`).

## Local effort

If `CLAUDE.local.md` gives an effort for a role (`implementer` or `git-operator`), pass it as the `effort` parameter when you delegate to that role. Change it with `/brigade-settings`.
